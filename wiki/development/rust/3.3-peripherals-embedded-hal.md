# 3.3. Доступ до периферії та `embedded-hal`

[До змісту](../../../README.md#зміст)

Периферією мікроконтролера керують через регістри. Бібліотеки Rust надають кілька рівнів доступу — від окремих бітів регістра до операцій на кшталт читання з датчика. [The Embedded Rust Book про регістри](https://docs.rust-embedded.org/book/start/registers.html)

| Рівень | Відповідальність |
| --- | --- |
| **PAC (Peripheral Access Crate)** | Надає типізований доступ до регістрів конкретного чипа. |
| **HAL (Hardware Abstraction Layer)** | Пропонує API для налаштування й використання GPIO, таймерів, I²C, SPI та іншої периферії чипа. |
| **BSP (Board Support Package)** | Враховує схему конкретної плати, наприклад підключення світлодіода чи вбудованого датчика. |

Ці рівні дають змогу відокремити налаштування плати від логіки застосунку. [The Embedded Rust Book про переносність](https://docs.rust-embedded.org/book/portability/)

`embedded-hal` визначає спільні трейти для синхронних операцій із периферією, а `embedded-hal-async` — інтерфейси для асинхронних операцій. Наприклад, драйвер I²C-датчика може працювати з однаковим трейтом на STM32 і Raspberry Pi Pico. На кожній платі її HAL налаштовує виводи, тактування й контролер шини. Для перенесення драйвера перевір версію трейту та підтримку потрібних операцій обома HAL. [Документація embedded-hal](https://docs.rs/embedded-hal/latest/embedded_hal/)
