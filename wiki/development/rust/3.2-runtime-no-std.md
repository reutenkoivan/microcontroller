# 3.2. Середовище виконання та `no_std`

[До змісту](../../../README.md#зміст)

На мікроконтролері прошивка може працювати в режимі **bare metal** — без операційної системи. Після скидання керування отримує стартовий код. Наприклад, `cortex-m-rt` ініціалізує статичні дані перед запуском прошивки й формує таблицю векторів для винятків і переривань. Розміщення коду та даних у Flash і RAM визначає сценарій компонувальника для конкретного пристрою. [Документація cortex-m-rt](https://docs.rust-embedded.org/cortex-m-quickstart/cortex_m_rt/)

Атрибут `no_std` дає крейту змогу обійтися без автоматичного підключення стандартної бібліотеки `std`. У такому середовищі базові можливості мови надає `core`. [The Embedded Rust Book](https://docs.rust-embedded.org/book/intro/no-std.html)

| Бібліотека | Що дає прошивці |
| --- | --- |
| `core` | Базові типи, ітератори, `Option` і `Result` без потреби в системному середовищі. [Документація core](https://doc.rust-lang.org/core/) |
| `alloc` | Колекції та розумні вказівники з динамічним виділенням пам’яті, зокрема `Vec` і `Box`. Для них прошивка має надати алокатор. [Документація alloc](https://doc.rust-lang.org/alloc/) |
| `std` | Стандартна бібліотека Rust із системними можливостями, доступними на конкретній цілі. Наприклад, Rust має цілі для ESP-IDF, під які можна зібрати `std`. [ESP-IDF у rustc Book](https://doc.rust-lang.org/rustc/platform-support/esp-idf.html) |

Для прошивки з фіксованим обсягом даних часто достатньо буферів заздалегідь визначеного розміру. Для колекцій змінного розміру до бюджету RAM потрібно включити область динамічної пам’яті. [The Embedded Rust Book про no_std і пам’ять](https://docs.rust-embedded.org/book/intro/no-std.html)
